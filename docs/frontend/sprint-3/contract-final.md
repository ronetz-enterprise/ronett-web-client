La liste est complète et non paginée. Les appartenances inactives restent visibles, sans permissions. OWNER est le seul rôle. Aucun endpoint de polling n’existe : la reprise rejoue le POST avec la même clé et le même contenu, pendant 30 jours. Une clé expirée n’est pas recyclée.

Cookie ronetz_refresh : HttpOnly, Secure par défaut, SameSite Strict, Path /api/auth/web, durée absolue serveur sept jours. Les mutations web exigent X-XSRF-TOKEN ; les endpoints bearer ne lisent pas ce cookie. Frontend/API doivent être sur le même site et l’origine exacte autorisée par CORS.

## Audit frontend avant modification

Correct : découpage app/pages/features/shared, client HTTP et ProblemDetail, session avec rotation coordonnée et invalidation des réponses tardives, cache par arbre SSR et clés tenant, formulaire partagé, sidebar shadcn, validation des réponses de création.

Les nouveaux contrôleurs et tests backend démontrent la correction des blocages contractuels précédents. Leur lecture ne remplace pas une exécution de tests contre le serveur réel dans cette intervention. Aucune dépendance ajoutée à ce stade.
